# Как устроены «Мои задачи» V2

## Структура

Это продолжение проекта V1 на React + Vite. Новое приложение или сервер не создавались.

- `src/main.jsx` запускает React в контейнере из `index.html`.
- `src/App.jsx` хранит общий список и собирает форму, прогресс, поиск и фильтры.
- `src/TaskItem.jsx` показывает задачу и подключает перетаскивание. В том же файле небольшой `TaskEditor` отвечает за черновик редактирования.
- `src/taskData.js` содержит проверку сохранённых данных, значения приоритетов и работу с календарными датами.
- `src/Icon.jsx` задаёт единый стиль функциональных SVG-иконок.
- `src/index.css` содержит шрифт, цвета обеих тем и общие правила. `src/App.css` — композицию и состояния элементов.

## React, состояния и ссылки

React обновляет интерфейс после изменения данных. `useState` хранит массив задач, значения формы, фильтр, поиск, тему и сообщения. У редактора свой черновик: набор текста не изменяет сохранённую задачу до нажатия Enter или «Сохранить».

`useRef` хранит ссылки на поля для управления фокусом, таймеры удаления и высоту строки. Изменение ref само по себе не перерисовывает интерфейс.

`useEffect` записывает изменения в localStorage, подключает горячие клавиши, проверяет смену календарного дня и настройку reduced motion. При закрытии компонента слушатели и таймеры очищаются.

`useLayoutEffect` в строке измеряет высоту редактора до показа кадра. Короткая анимация делает открытие и закрытие формы плавным. При reduced motion она отключена.

## Формат задачи

```js
{
  id: 'уникальный-идентификатор',
  text: 'Отправить тестовое задание',
  completed: false,
  priority: 'medium',
  dueDate: '2026-11-15' // или null, если срока нет
}
```

Идентификатор создаётся через `crypto.randomUUID()`. Названия могут совпадать: для действий и ключей React используется id. Порядок задаётся положением объектов в массиве; отдельное поле order не нужно.

## Добавление, выполнение и удаление

Форма вызывает `addTask` по кнопке и Enter. `preventDefault` отменяет перезагрузку. `trim()` убирает пробелы по краям; пустые строки отклоняются. Поле ограничено 200 символами. После добавления оно очищается и получает фокус.

Чекбокс меняет `completed` только у нужного id через `map`. Для удаления используется `filter`. Исходный массив не изменяется: React получает новый массив. Неизменённые свойства задач сохраняются.

Удаление сразу исключается из данных, записываемых в localStorage. Строка остаётся на 180 мс для исчезновения и сжатия; поэтому быстрое обновление страницы не возвращает удалённую задачу. Фокус переходит к соседней задаче или в поле добавления.

## Редактирование

Кнопка с карандашом открывает форму внутри строки. `TaskEditor` получает текущие текст, приоритет и срок и копирует их в локальный черновик. Enter и «Сохранить» проверяют название и передают изменения в App. Объект обновляется через `{ ...task, ...changes }`, поэтому id и статус не теряются.

Escape и «Отмена» закрывают черновик без изменения задачи. Пустое название блокирует сохранение. После завершения фокус возвращается к кнопке редактирования; если задача перестала подходить поиску, фокус остаётся в поиске.

## Drag & Drop

`DragDropProvider` из dnd-kit принимает события перетаскивания. Каждая строка вызывает `useSortable` с id и индексом. Отдельный `handleRef` подключает ручку: чекбокс, текст и кнопки не запускают перенос.

Для мыши нужен небольшой сдвиг, для касания — удержание около 220 мс. У ручки задан `touch-action: none`; остальная часть списка прокручивается обычным образом.

При отпускании App берёт начальный и конечный индекс и переставляет объект в копии массива. Затем общий эффект сохраняет порядок. Escape отменяет перенос. Клавиатура поддерживает пробел и стрелки; Alt + вверх/вниз сразу меняет позицию на одну. Поиск, фильтр или открытый редактор временно блокируют сортировку.

## Приоритеты

Приоритет хранится как `low`, `medium` или `high`; по умолчанию medium. В интерфейсе показаны текст «Низкий / Средний / Высокий» и маленькая цветовая метка. Цвет дополняет текст. Значение выбирается при создании и меняется в редакторе, в том числе у выполненной задачи.

## Дедлайны и часовые пояса

Нативное поле `type=date` отдаёт дату в формате YYYY-MM-DD. Она сохраняется как строка без часов. Текущая дата собирается из локальных года, месяца и дня, а не из UTC-времени.

Просрочка — это `dueDate < today` у невыполненной задачи. В день дедлайна просрочки нет. Выполненные задачи не считаются просроченными. Каждую минуту и при возврате фокуса проверяется смена дня. Для подписи дата форматируется как локальная календарная дата в полдень; это предотвращает сдвиг из-за трактовки YYYY-MM-DD как UTC.

Срок можно изменить или убрать кнопкой «Убрать срок» в редакторе. Неверные даты из хранилища заменяются на null при чтении.

## Поиск, фильтры и прогресс

Поиск сравнивает названия и запрос в нижнем регистре. Он работает сразу и сочетается со статусом задачи. `filter` создаёт отображаемую часть массива, сохраняя исходные задачи и порядок. Перезагрузка сбрасывает поисковый запрос и фильтр, а список остаётся сохранённым.

Счётчик и шкала вычисляются от всего массива. Формула процента — выполнено / всего × 100 с округлением. У пустого списка процент равен нулю. Отдельное состояние для процента не нужно.

Клавиша `/` переводит фокус в поиск только вне полей ввода. Первое Escape очищает запрос, повторное снимает фокус. В редакторе Escape отменяет черновик.

## Темы

Все основные цвета — CSS-переменные. Атрибут `data-theme` на html выбирает набор для светлой или тёмной темы. Короткий скрипт в head читает настройку до CSS и React, поэтому неправильная тема не успевает появиться. При первом открытии используется `prefers-color-scheme`.

Переключатель меняет атрибут и сохраняет выбор в `todo-list.theme`. Фоны, поля, границы, приоритеты, просрочка и состояния кнопок имеют отдельные цвета для обеих тем. Переходы длятся около 200 мс; reduced motion отключает их и анимации dnd-kit.

## localStorage и совместимость с V1

localStorage хранит строки в профиле браузера для конкретного адреса сайта. `JSON.stringify` превращает массив в строку; `JSON.parse` читает его обратно. Ключ списка сохранён: `todo-list.tasks.v1`.

При чтении проверяются массив, уникальные строковые id, названия и логические статусы. Задачам V1 добавляются безопасные значения medium и null; id, текст, статус и порядок сохраняются. Первое открытие ничего не перезаписывает. Перед первой записью перенесённого списка сохраняется исходное значение в `todo-list.tasks.v1.backup`, если резервной копии ещё нет.

Повреждённые данные не перезаписываются до действия пользователя. Ошибки чтения, квоты и запрета доступа обрабатываются через try/catch: интерфейс продолжает работать, но сообщает об ограничении сохранения. Данные привязаны к браузеру, не синхронизируются между устройствами и удаляются при очистке данных сайта.

## Адаптивность и доступность

На компьютере рабочая область ограничена 1040 px: форма и прогресс слева, список справа. На планшете и телефоне блоки перестраиваются; на узком экране кнопки строки переходят ниже текста. В коротком горизонтальном окне боковая форма перестаёт быть sticky.

`min-width: 0` и перенос длинных слов предотвращают переполнение. Основные кнопки имеют область 44×44 px и видимы без hover. У полей есть названия, у иконок-кнопок — aria-label, у прогресса — доступное описание. Удаление и редактирование восстанавливают фокус.

## AI и проверка

OpenAI Codex использовался для анализа V1 и референсов, реализации, исправлений, автоматизированных тестов, визуального ревью и документации. Playwright проверяет поведение в браузерах, axe — часть требований доступности. Проверки и ограничения перечислены в TESTING.md. AI API внутри приложения нет.

## Запуск

В папке проекта выполните `npm install` и `npm run dev`. Для готовой сборки — `npm run build` и `npm run preview`. Проверка кода: `npm run lint`, браузерные сценарии: `npm test`. Первый запуск тестов может потребовать установки браузеров по README. Публикация описана в DEPLOYMENT.md.
