# Публикация

Проверенная сборка находится в `dist/`, настройки — в `netlify.toml`. Публичный репозиторий и сайт пока не созданы: сохранённый доступ GitHub вернул HTTP 401, локальная авторизация Netlify не найдена. Пароли и токены в проект не добавлялись.

## 1. Войти в GitHub

В терминале выполните команду установленного Git Credential Manager и завершите вход в своём браузере:

```sh
git credential-manager github login --url https://github.com --web --force
```

`--force` здесь обновляет вход в аккаунт, а не выполняет force push. Выберите нужный личный аккаунт в браузере. Пароль или токен в чат отправлять не нужно.

## 2. Создать новый публичный репозиторий

Откройте [создание репозитория GitHub](https://github.com/new), выберите личный аккаунт и имя `todo-list-react`. Если оно занято, выберите другое. Создайте **пустой** публичный репозиторий без автоматически добавленных README, лицензии и .gitignore.

В папке проекта добавьте адрес именно нового репозитория и отправьте текущий коммит в `main`:

```sh
git remote add origin https://github.com/YOUR_LOGIN/todo-list-react.git
git push -u origin HEAD:main
```

Замените `YOUR_LOGIN` и имя репозитория на фактические. У проекта сейчас нет `origin`; если он уже добавлен, сначала проверьте `git remote -v`. Не используйте force push и не направляйте код в чужой или существующий непустой репозиторий.

## 3. Создать отдельный проект Netlify

Войдите в [Netlify](https://app.netlify.com/) и создайте новый проект из GitHub-репозитория. Выберите только что созданный репозиторий и ветку `main`.

- Build command: `npm run build`.
- Publish directory: `dist`.
- Node.js: 24 (также задан в `netlify.toml`).
- Переменные окружения и сервер не нужны.

Используйте бесплатные возможности, отдельный новый адрес Netlify и не выбирайте существующий сайт для обновления. Настройки соответствуют [официальной инструкции Vite на Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/vite/).

Альтернатива без привязки GitHub: после входа откройте [Netlify Drop](https://app.netlify.com/drop) и загрузите папку `dist` как новый проект. Исходники всё равно нужно отдельно разместить на GitHub.

## 4. Проверить опубликованный адрес

Откройте итоговый HTTPS-адрес. Добавьте две задачи кнопкой и Enter, выполните одну, обновите страницу, убедитесь в сохранении текста и статуса. Удалите задачи и проверьте телефонную ширину. В инструментах браузера проверьте отсутствие ошибок JavaScript и загрузки ресурсов.

Автотесты можно направить на публикацию (PowerShell):

```powershell
$env:PLAYWRIGHT_BASE_URL = 'https://ВАШ-НОВЫЙ-ПРОЕКТ.netlify.app'
npm test
Remove-Item Env:PLAYWRIGHT_BASE_URL
```

Тесты используют изолированные браузерные контексты; они не меняют список в вашем обычном профиле браузера. После успешной проверки добавьте реальные ссылки в README и сделайте обычный коммит и push.
