# Публикация и обновление

Исходный код: [ssvoboka/todo-list-react](https://github.com/ssvoboka/todo-list-react). Production-ветка — `main`.

## Настройки Netlify

- Framework: Vite.
- Build command: `npm run build`.
- Publish directory: `dist`.
- Node.js: 24.
- Production branch: `main`.

Настройки сборки и заголовки заданы в `netlify.toml`. Переменные окружения, сервер и платные дополнения приложению не нужны. Шрифты и уведомления о лицензиях включены в `dist/`.

## Обновление

Перед отправкой изменений выполните:

```sh
npm ci
npm run lint
npm run build
npm test
```

Закоммитьте проверенные изменения. Для текущего локального проекта отправка в production-ветку выполняется обычным push без force:

```sh
git push origin HEAD:main
```

После подключения Git-интеграции Netlify получает коммиты ветки `main` и собирает сайт. Публичную ссылку и подтверждённый статус автоматического обновления смотрите в README.

## Проверка опубликованной версии

Откройте HTTPS-адрес и проверьте добавление, выполнение, редактирование, удаление и сохранение после reload. Дополнительно проверьте обе темы, сроки, приоритеты, поиск, фильтры, прогресс и порядок задач. На телефоне проверьте перенос за ручку и обычную прокрутку.

Автотесты можно направить на публичную версию (PowerShell):

```powershell
$env:PLAYWRIGHT_BASE_URL = 'https://ВАШ-ПРОЕКТ.netlify.app'
npm test
Remove-Item Env:PLAYWRIGHT_BASE_URL
```

Они используют изолированные браузерные контексты и не меняют задачи в обычном профиле пользователя.

Результаты проверки записываются в TESTING.md. Авторизация GitHub и Netlify хранится средствами официальных CLI вне репозитория; секреты не должны попадать в исходники, коммиты и README.
